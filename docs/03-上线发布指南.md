## 2. 阶段 A：上线前的服务端准备

### A1. 本机开发期继续用 IP 联调（上线前的过渡期）

在拿到域名/证书之前，不需要阻塞开发：

1. 后端 `uvicorn` 改为监听局域网地址：`uvicorn app.main:app --host 0.0.0.0 --port 8000`（Windows 防火墙放行 8000）。
2. 小程序端 API base 指向 `http://<你的局域网IP>:8000`（手机与电脑同一 Wi-Fi）。
3. 微信开发者工具右上角「**详情 → 本地设置 → 勾选『不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书』**」，即可在工具与**真机预览**中调用本机 HTTP 接口。
4. 建议把 API base 做成环境可切换（见 A8），按 `wx.getAccountInfoSync().miniProgram.envVersion` 的 `develop / trial / release` 自动切开发/体验/正式地址，避免将来手动改。

> 注意：**该勾选只对开发者工具与预览生效，体验版/正式版仍会强制校验**。上线链路必须走合法域名的 HTTPS（官方网络能力说明见[《网络-使用说明》](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)）。

### A2. 域名与小程序备案（最优先启动）

**两条线并行做**：a）买域名并申请 ICP 备案（1~3 周）；b）提交**小程序备案**（1~2 周）。两者独立、都耗时长，越早提交越好。

**小程序备案**（微信侧，决定能否上架）：
- 依据：微信官方要求，2023-09-01 起**新上架小程序必须备案**；存量小程序也已分批要求补备案，未备案将面临下架（见[环球网报道](https://m.huanqiu.com/article/4E3eRHp2qnA)、[微信开放社区-备案问答](https://developers.weixin.qq.com/community/develop/article/doc/00060696d3c0a851fc30af38761013)）。
- 入口：登录 [微信公众平台](https://mp.weixin.qq.com) → 小程序管理后台 → **「设置」或首页的「小程序备案」入口**（未备案时后台会有明显的备案引导卡片/悬浮入口）。
- 个人主体材料：本人身份证正反面、手机号、应急联系方式；**不需要营业执照**。
- 流程：微信平台初审 → 管局审核 → 备案通过，获得备案号并显示在小程序「关于」页。
- 时长：官方无硬性承诺，社区经验个人主体通常**平台初审 1~3 个工作日 + 管局审核 1~20 个工作日，合计约 1~2 周**；如遇身份核验问题（如负责人手机号一致性）会延长（以官方当前处理进度为准）。
- 全部**免费**，谨防任何收费代办。
- 补充参考：[2026 小程序备案指南（流程+避坑+FAQ）](https://www.gq680.com/h-nd-99281.html)、[微信小程序备案是必须的吗？怎样才能发布上线](https://www.xiaohuokeji.com/index.php/archives/xiaochengxukaifa/1173)、[小程序备案指南（官方社区，持续更新）](https://developers.weixin.qq.com/community/develop/article/doc/0008403911c1107ec14043aef66813)。

**域名 ICP 备案**（云厂商侧，决定能否用国内服务器 + HTTPS 合法域名）：
- 在腾讯云/阿里云购买域名（如 `xxx.com`）后，用**同一账号**提交 ICP 备案：个人主体也是身份证即可，云服务器（或备案授权码）为必填项，所以在提交域名备案前**先买好云服务器/轻量应用**。
- 建议域名与小程序备案的**主体保持一致**（都是你本人），避免后续校验不一致。
- 备案期间服务器可以先搭建调试（通过 IP 访问），备案通过后再绑定域名。

### A3. 云服务器部署（简版建议，细节可参照 docs/02 的架构）

推荐 **腾讯云轻量应用服务器（Lighthouse）2 核 2G 起步、系统 Ubuntu/Debian**（面向小程序的小成本选择，社区部署指南可参考[腾讯云-部署指南（备案、SSL、审核）](https://cloud.tencent.com.cn/developer/article/2704534)）：

1. 装 MySQL 8（或直接用云数据库 MySQL，免运维）。
2. 装 Python 3.13 + uv（沿用 docs/02 的依赖管理方式），拉取 `server/` 代码，`uv sync` 装依赖。
3. 数据库迁数：本机 `mysqldump` 导出 → 服务器导入（上线前做，见 §8 备份）。
4. 用 systemd 托管 FastAPI：

   ```ini
   # /etc/systemd/system/goodgoodeat.service
   [Unit]
   Description=GoodGoodEat FastAPI
   After=network.target mysql.service
   [Service]
   User=www-data
   WorkingDirectory=/opt/good-good-eat/server
   ExecStart=/opt/good-good-eat/server/.venv/bin/uvicorn app.main:app \
     --host 127.0.0.1 --port 8000 --workers 2
   Restart=always
   [Install]
   WantedBy=multi-user.target
   ```

   `systemctl enable --now goodgoodeat` 开机自启。
5. nginx 反向代理 80/443 → `127.0.0.1:8000`（A4/A5 一起配）。

**安全底线**（个人项目也务必做到）：
- `.env` 不入库；`WX_APPID`/`WX_SECRET` 只在服务器上配置。
- MySQL 只监听内网（`bind-address=127.0.0.1`）或云数据库白名单，**不对公网开放 3306**。
- 服务器安全组只放行 80/443/22。

### A4. HTTPS 与 SSL 证书

为什么必须 HTTPS：小程序 `wx.request`/`wx.uploadFile` 等**只允许 https://**，且域名需已 ICP 备案；WebSocket 只允许 `wss://`。HTTPS（证书）负责传输加密，ICP 备案负责域名在国内的合规解析与服务资质——**两者都要，不能互相替代**（参见[新网-小程序上线必过三关：备案、HTTPS、CDN](https://www.xinnet.com/knowledge/2142348599.html)）。

操作：
1. 云厂商控制台申请**免费 DV 证书**（腾讯云/阿里云均有，通常 1 年）或 Let's Encrypt（90 天需续期）。
2. DNS 解析：`api.你的域名.com → 服务器公网 IP`。
3. nginx 配置 443 并替换证书路径；`http://80` 301 跳转 `https://`。

### A5. 公众平台「服务器域名」配置（含 WebSocket）

位置：微信公众平台 → **开发 → 开发管理 → 开发设置 → 服务器域名**。
配置内容（本项目需要两类）：

| 类别 | 填什么 | 说明 |
|------|--------|------|
| `request` 合法域名 | `https://api.你的域名.com` | REST API（FastAPI `/api/v1/**`） |
| `socket` 合法域名 | `wss://api.你的域名.com` | **第三期 WebSocket** `/ws/team/{teamId}` 必须配这个，否则连不上 |
| `uploadFile` 合法域名 | （本项目暂无需） | 如需上传图片再配 |
| `downloadFile` 合法域名 | （本项目暂无需） | 菜品图片若用 CDN 再配 |

要点：
- 每个新增域名需**下载校验文件放到服务器对应路径**验证所有权。
- 修改需**管理员扫码确认**，且官方对修改次数有限制（每月有限次，以官方当前页面为准）——**先把域名规划好一次性配齐**。
- 三方平台/开放接口方式见[官方-配置小程序服务器域名](https://developers.weixin.qq.com/doc/oplatform/openApi/miniprogram-management/domain-management/api_modifyserverdomain.html)；普通个人主体直接在后台手动配即可。
- 常见报错「xxx 不在以下 request 合法域名列表中」→ 就是这里没配或配错，含大小写/协议不一致，排查见[腾讯云-合法域名报错解决](https://cloud.tencent.com.cn/developer/article/2600855)。

**nginx 同时要为 WebSocket 升级协议放行**（第三期提前备好）：

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}
server {
    listen 443 ssl http2;
    server_name api.你的域名.com;
    ssl_certificate     /etc/letsencrypt/live/api.你的域名.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.你的域名.com/privkey.pem;

    location /api/ { proxy_pass http://127.0.0.1:8000; }
    location /ws/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_set_header Host $host;
    }
}
server { listen 80; server_name api.你的域名.com; return 301 https://$host$request_uri; }
```

### A6. 后端配置变更清单

| 配置项 | 开发（本机） | 生产（云服务器） |
|--------|--------------|------------------|
| `server/.env` 中 `WX_APPID` | 测试/当前 AppID | **正式号 AppID**（见 §6） |
| `WX_SECRET` | 测试号密钥 | 正式号密钥（仅服务器保存） |
| 数据库连接 | 本机 MySQL8 | 云 MySQL/服务器 MySQL |
| `API_BASE_URL`（小程序端） | `http://127.0.0.1:8000` | `https://api.你的域名.com` |
| CORS | 小程序 `wx.request` **无浏览器同源限制**，不需要 CORS；如日后有网页端再配 | 同左 |

> 小程序 `wx.request` 与浏览器不同，**没有跨域问题**，不用在 FastAPI 里配 CORS 中间件（配了也不影响，不配也没关系）。

## 3. 阶段 B：开发者工具与公众平台发布

**大流程**：开发者工具上传代码 → 后台设体验版 → 体验成员真机自测 → 提交审核 → 审核通过 → 发布上线。
（整体流程可参考[微信小程序发布流程详解](https://m.yisu.com/zixun/1066843.html)与[版本差异全解析：开发版/体验版/审核版/线上版](https://blog.csdn.net/sg_knight/article/details/147385334)。）

### B1. 类目选择（本项目关键决策）

**建议类目：工具类**（个人主体可申请的范围内选「工具」相关类目，如「工具 → 生活工具/效率工具」，实际以后台「设置-基本设置-服务类目」中个人主体可选列表为准；选择时用「菜谱/点菜」关键词搜索可用项）。

做出这个选择的判断依据（写进审核备注也成立）：
- 本项目是**个人使用的美食记录/决策工具**：多人点菜、生成菜单给厨师看，**无支付、无商品售卖、无配送、无商家入驻**——不属于经营性餐饮/电商业务。
- 「餐饮服务 / 外卖点餐 / 食品交易」类目往往要求**营业执照 + 食品经营许可证**等资质，个人主体无法提供；**只要不碰交易与经营，就不需要食品经营许可证**。
- 个人主体只能申请**微信开放的服务类目**中的有限范围；后台类目选择器会自动过滤出当前主体可选的类目，选类目时即可验证（参见官方社区置顶[个人主体未开放类目修改指引](https://fuwu.weixin.qq.com/community/develop/doc/000cc6ea4ec3c8808b6eef7b356009)与[个人开发者独立申请小程序指南](https://www.yztd.com.cn/yunying/38684.html)）。
- 资质参考（官方，小商店个人开放类目场景）：[微信小商店-个人开放类目商品资质要求](https://developers.weixin.qq.com/miniprogram/product/mini-store/leimuzizhi/gerenshangpinxin.html)——再次强调：**我们不走开店/交易，类目选「工具」，与资质门槛解耦**。

**先选对类目再提审**：类目与功能不匹配是常见驳回原因（见 §7）。

### B2. 基本设置完善（审核前置项）

后台「**设置 → 基本设置**」：小程序名称（好大一颗菜）、头像、简介、服务类目、地区、登录配置等全部填齐且**与功能一致**。名称/简介不要写"外卖""点餐下单给商家"等经营性表述，建议如"家人好友一起点菜、给厨师看的做菜清单工具"。

### B3. 上传代码（微信开发者工具）

1. 打开项目，右上角「**上传**」按钮（需项目已绑定**你的 AppID**；未绑定开发者身份时，先在后台「管理-成员管理」把你设为开发者，个人主体默认账号即是管理员可上传）。
2. 填写**版本号**（语义化递增，如 `1.0.0`，后续 `1.0.1`…）与**项目备注**（此次改动说明，方便审核与回滚追溯）。
3. 上传成功后，代码出现在后台「**版本管理 → 开发版本**」。

版本号规范建议：`主.次.修订` 三段式；**每次上传必须大于等于上一版本且不能重复**；正式发布版本与体验版本号保持一致便于追溯。

### B4. 设为体验版 + 体验成员

1. 后台「**版本管理 → 开发版本**」→ 对应版本点「**选为体验版**」→ 生成**体验版二维码**。
2. 后台「**管理 → 成员管理 → 体验成员**」添加家人/好友（数量上限以后台显示为准）。
3. 体验成员用自己的微信扫码即可进入**体验版**（体验版仍会校验合法域名和 HTTPS！这也正是先配域名的原因）。
4. 在体验版上完整走一遍：**游客路径（不开微信登录直接点菜下单）+ openid 登录路径**、多端实时同步（WebSocket 三期）、厨师接单流程。

### B5. 提交审核

后台「**版本管理 → 开发版本**」→ 该版本「提交审核」：
- 按提示选择**页面路径、类目**（会自动带入已选类目）。
- 填写**审核备注**：写清楚"家庭多人点菜/做菜工具类小程序，不涉及支付交易，无需经营资质；游客模式可直接完整体验"，附**测试账号/演示路径说明**（个人主体无企业测试账号，最好保证游客可完整体验全流程，审核员才能点通）。
- 审核时长：通常 1~7 个工作日（以官方当前进度为准）；期间可撤回重新提交。

官方对代码审核的通用要求与常见驳回依据见[微信开放文档-代码审核](https://developers.weixin.qq.com/miniprogram/product/reject.html)。

### B6. 审核通过后发布

1. 审核通过后版本进入「**版本管理 → 审核版本**」。
2. 点「**发布**」→ 默认**全量发布**（如后台提供「分阶段发布」灰度入口可自行选择，以官方页面为准）。
3. 发布后小程序立即对全量用户生效；几分钟后可在微信搜索到你发布的小程序（个人工具类不做搜索优化亦可）。

### B7. 发布后立即核对

- [ ] 「关于」页显示备案号
- [ ] 真机从搜索/扫码进入线上版，游客与登录两条路径都通
- [ ] 服务器日志无 5xx、MySQL 连接正常
- [ ] HTTPS 证书无告警（https:// 打开接口返回正常）

## 4. 阶段 C：隐私与合规

### C1. 本项目实际收集的数据盘点

| 数据类型 | 来源 | 用途 | 是否属于隐私接口触发项 |
|----------|------|------|------------------------|
| openid（身份标识） | 前端 `wx.login` 拿 code → 后端 `code2session` 换 openid | 用户识别/团队绑定/订单归属 | 登录能力（官方[小程序登录](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)、[登录凭证校验 code2session](https://developers.weixin.qq.com/miniprogram/dev/server/API/user-login/api_code2session.html)、[wx.login](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/login/wx.login.html)） |
| 昵称 | 用户**主动填写**（头像昵称填写能力） | 展示在团队/点菜列表 | 无接口触发，但需在隐私指引中声明 |
| 头像 | 用户**主动选择**（头像昵称填写能力） | 用户展示 | 选择头像组件属隐私接口，需有隐私协议 |
| 订单/点菜/团队数据 | 用户使用产生，存服务端 MySQL | 核心业务 | 业务数据，隐私指引"订单信息/日志"类声明 |
| 设备/位置 | **不收集** | — | 不要引入位置授权（本项目不需要） |

> 头像昵称获取方式：2022-10 之后**不再支持静默 `wx.getUserProfile` 拿头像昵称**，官方改为「头像昵称填写能力」（`<button open-type="chooseAvatar">` + `<input type="nickname">`，由用户主动选择/填写）。本项目如果当前还是 getProfile 方案，**必须改**，否则审核大概率被拒（参见[官方社区公告](https://fuwu.weixin.qq.com/community/develop/doc/00088c6f204420961590fcf8a60000)与[替代方案说明](https://cloud.tencent.com.cn/developer/article/2245051)）。

### C2. 用户隐私保护指引填写要点

位置：后台「**设置 → 服务内容声明 → 用户隐私保护指引**」（或「开发管理」内对应入口），需**填写后保存并发布**。

本项目建议勾选/声明的信息类型（以后台选项为准）：
- **用户信息**：昵称、头像（注明"由用户主动填写/选择"）
- **身份认证信息**：登录凭证（openid 相关，写明"用于账号识别，由微信登录接口生成"）
- **订单/业务数据**：点菜记录、团队信息（写明"存于开发者服务器，用于点菜与做菜协作"）
- 不要勾选：位置、相册/相机读取、通讯录等（本项目不涉及）

同时：
- 隐私指引中给出**客服/联系方式**与**数据使用范围说明**（个人开发者填邮箱即可）。
- 官方开发者指南：[小程序隐私协议开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)；实操参考[小程序隐私保护指引设置](https://cloud.tencent.com.cn/developer/article/2603190)。

### C3. 前端隐私弹窗要点

- 2023 年后官方要求：**涉及隐私接口的调用需先取得用户同意**（弹隐私协议），`chooseAvatar`、`chooseMedia` 等均算。
- 本项目最小合规做法：在**首次进入**时展示隐私协议弹窗（文案 = 后台填写指引的摘要），明确"不授权也可用游客身份浏览点菜；授权仅用于展示你的昵称头像"；用户拒绝则继续用游客模式，**不得强制授权**（强制授权是常见驳回点）。
- 方案二选一：用官方默认隐私弹窗（配置了指引后自动出现），或自建 `wx.onNeedPrivacyAuthorization` 流程并按官方[隐私协议开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)实现。

### C4. 测试号 vs 正式号（合规层面差异）

| 维度 | 测试号/测试 AppID | 正式小程序账号 |
|------|-------------------|----------------|
| 能否发布上线 | ❌ 不能上传/审核/发布 | ✅ 完整流程 |
| 服务器域名配置 | 无需（也不可用） | 必须配置并校验 |
| 隐私指引 | 不需要 | **必须填写并发布** |
| 备案 | 不需要 | **必须完成** |
| 体验成员/线上用户 | 仅本地预览 | 正式对外 |

## 5. 阶段 D：正式号迁移（测试标识 → 正式账号）

### D1. 先确认你的 AppID 到底是什么

在微信开发者工具「**详情 → 基本信息**」查看当前 AppID（`wx6056573ab9ee889b`），然后：
- 用该 AppID 能否登录 [微信公众平台](https://mp.weixin.qq.com)（小程序后台）？
  - **能登录** → 这是正式注册账号，可直接走 §1 清单（需补备案等）。
  - **不能登录 / 只是在工具里换的测试号** → 当前是**测试号**，**无法发布**。需先到微信公众平台用本人微信**注册一个小程序**（个人主体免费）：注册后获得新的正式 AppID，按 §2~§4 完成备案/域名/隐私后发布，本项目代码无需大改（AppID 是配置项）。
- 判断方法补充：正式账号后台「设置-基本设置」能看到主体名称、账号信息；测试号没有独立后台。
- 参考阅读（社区文章，判断思路可参考）：[小程序测试号转正？别急着提交](https://www.whbaitui.com/news/26420.html)、[小程序测试号，开发者的"陷阱"还是"捷径"？](https://www.whbaitui.com/news/175368.html)。

### D2. openid 体系与数据影响（重点）

- **openid 是按 AppID 隔离的**：同一微信用户，在不同 AppID 下得到的 openid **完全不同**（微信把 AppID 纳入身份计算）。因此**测试号时期产生的用户记录，与正式号用户记录天然不互通**（依据：官方登录文档对 openid 的定义，[小程序登录](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)）。
- 对本项目的影响（数据个人使用为主，总体可控）：
  1. 测试期内绑在某条测试号 openid 上的团队/订单/昵称，切换正式号后**这些用户会变成"新用户"**（新 openid 建新档案）。
  2. **游客模式（`users.is_guest=1`）基本不受影响**：游客身份不依赖 openid（取决于实现；若游客标识也是服务端生成的匿名 ID 则无缝，若借助 openid 生成则同样会"换新"）。§8 备份数据、按需迁移即可。
  3. 若确实需要保留测试期数据：发布正式号后，让老用户在正式号首次登录一次，后端**人工建立测试号 openid ↔ 正式号 openid 映射表**，再跑迁移脚本合并用户与订单——个人项目一般不值得做，**建议直接以正式号为新起点**，测试期数据仅作功能验证。

### D3. 切换 AppID 配置变更清单

| 位置 | 改什么 | 注意 |
|------|--------|------|
| 后端 `server/.env` | `WX_APPID` → 正式号 AppID；`WX_SECRET` → 正式号密钥 | 密钥在后台「开发管理-开发设置-AppSecret」查看/重置；**只放服务器**，勿提交 git |
| 微信开发者工具 | 「详情-基本信息」把 AppID 换为正式号（或重新导入项目） | 换 AppID 后原 project.config.json 中的 appid 字段同步；`touristappid` 等测试标识替换 |
| 小程序端配置 | API base 切到 `https://api.你的域名.com`（按 A8 的 envVersion 自动切更稳） | 体验版即走正式 HTTPS 链路 |
| 数据库 | 确认游客/用户表结构无需改（openid 字段按新 AppID 存） | 若表按 openid 唯一索引，天然兼容 |
| 后台 | 服务器域名、隐私指引、类目、成员管理 | 与正式号 AppID 绑定，测试号时期配置不通用 |

参考[官方-代码审核](https://developers.weixin.qq.com/miniprogram/product/reject.html)与[微信小程序平台常见拒绝情形](https://m.w3cschool.cn/miniappbook/miniappbook-reject.html)整理：

| 驳回原因 | 本项目风险点 | 规避措施 |
|----------|--------------|----------|
| 功能不完整/无法完整体验（空白页、登录墙） | 高 | 游客模式必须能走通"浏览→点菜→下单→看到取餐码→查订单"全流程；不强制登录、不开启动页广告 |
| 类目不符/资质问题 | 高（选错类目会被要求资质） | 选「工具」类；审核备注写明"无交易无支付无需食品经营资质"；不出现"外卖/商家/收款"表述 |
| 隐私问题：未填指引、强制授权、超范围收集 | 高 | 按 §4 填指引+合规弹窗；授权可拒绝且拒绝可继续用 |
| 诱导分享/强制关注 | 中 | 分享按钮做成**用户自愿**（不要"分享才能看结果"）；不引导关注公众号 |
| 名称/简介与功能不符或含敏感/夸大词 | 中 | 名称简介中性描述工具用途 |
| 页面崩溃/报错/接口失败 | 中 | 体验版多机型真机自测；后端错误兜底（接口失败给友好提示而非白屏） |
| UGC 无管控（本项目无 UGC） | 低 | 若后续加评论/留言，需内容过滤+举报入口 |
| 版本内容与审核版本不一致 | 低 | 体验版自测的就是即将提审的版本 |

**提交前自检建议**：录一遍游客全流程视频（可作审核备注材料），在工具与 2 台以上真机上跑通；所有报错清除。

## 7. FAQ

**Q1：备案要多久？免费吗？**
个人主体提交小程序备案，通常平台初审 1~3 工作日 + 管局审核 1~20 工作日，合计约 1~2 周；**免费**。域名 ICP 备案类似量级。两者都要预留时间，别压到最后。

**Q2：个人主体能发布小程序吗？有哪些限制？**
能。个人主体可发布，但：可选服务类目有限（工具/生活服务类可用，餐饮经营、直播、支付类不可）；**不能开通微信支付**（本项目不需要）；部分能力（如部分插件、客服消息增强、搜索收录的某些位）受限。类目可用范围以后台选择器实际可选项为准（见[官方社区-个人主体未开放类目修改指引](https://fuwu.weixin.qq.com/community/develop/doc/000cc6ea4ec3c8808b6eef7b356009)）。

**Q3：能跳过备案吗？用海外服务器行不行？**
不能跳过。新上架必须备案，存量未备案会被下架。**海外服务器无法备案**（备案要求境内接入商与服务器），且小程序 `request` 校验会拦掉未备案域名——所以**必须用国内云服务器 + 已备案域名**这条路。（依据：[环球网-9月1日起须备案](https://m.huanqiu.com/article/4E3eRHp2qnA)、[新网-备案+HTTPS 指南](https://www.xinnet.com/knowledge/2142348599.html)）

**Q4：必须 HTTPS 吗？**
必须。`request`/`socket` 只放行 https:// 与 wss://（且域名已备案）。开发期可在工具勾选"不校验合法域名/HTTPS 证书"调试，上线无豁免。

**Q5：测试号的数据能带到正式号吗？**
openid 按 AppID 隔离，**用户数据不自动互通**。本项目数据个人使用为主，建议以正式号为新起点；必要时的映射迁移见 §5 D2。

**Q6：需要食品经营许可证吗？**
不需要。本项目不做交易、不卖食品、无配送，是工具/记录类；选「工具」类目即可规避资质要求。若你将来做"附近商家点餐下单"等经营性功能，才需要企业主体+相应资质。

**Q7：服务器域名改起来麻烦吗？**
每次新增/修改需管理员扫码 + 下载校验文件验证所有权，且**每月修改次数有限**（以官方当前页面为准）——所以域名规划一次到位（request + socket 同时配）。

**Q8：上线后想回退怎么办？**
「版本管理 → 线上版本」支持**回退到上一次线上版本**（具体条件与限制以官方页面为准）；更常规的做法是快速修复后上传新版本走体验→审核→发布覆盖，同时可用「暂停/下线」兜底。参见[腾讯云-小程序的版本发布与回滚](https://cloud.tencent.com.cn/developer/article/2492074)。

**Q9：WebSocket 第三期上线需要什么？**
`wss://` 域名 + 后台 **socket 合法域名**配置 + nginx 升级协议代理（§A5 已给配置）。开发期联调同样依赖"不校验域名"勾选与局域网。

**Q10：审核一般多久？防驳回的秘诀是什么？**
通常 1~7 个工作日（无保证）。"秘诀"是：功能完整可体验（游客路径通）、类目与简介自洽、隐私合规、无诱导行为——把 §6 自查表过一遍再提交。

## 8. 上线后运维

- **版本管理**：每次改动走「上传新版本 → 设体验版自测 → 提审 → 发布」，保留可回退的线上历史版本；版本号持续递增。
- **反馈收集**：个人项目用最简单的「关于/我的」页放邮箱/微信反馈入口即可；微信后台「成员管理-体验成员」持续邀请家人朋友当内测用户。
- **更新节奏建议**：功能小步快发（完成一个闭环发一版），避免大版本憋太久；发布前一周先在体验版跑。
- **数据备份**：数据库每日定时 `mysqldump` 到本地/对象存储：

  ```bash
  mysqldump -u<user> -p<pass> good_good_eat | gzip > backup_$(date +%F).sql.gz
  ```

  建议 cron 每日执行 + 保留最近 30 天；上线迁移前、重大版本发布前手动再备一次。
- **可观测性**：nginx 与 uvicorn 日志落盘、定期看 5xx；个人项目不必上监控系统，但至少跑一个「健康检查」接口（如 `/healthz` 探活）。
