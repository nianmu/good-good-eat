## 0. 架构总览（当前生产形态）

```
浏览器 / 域名或有 IP:7788
        │
        ▼
nginx (:7788)  ──静态→  /opt/good-good-eat/h5_dist/        （H5 SPA，备份于 h5_dist_bak_*）
        │  /api/ /ws/（含 WebSocket upgrade）
        ▼
uvicorn app.main:app (:8000, workers=2, systemd: goodgoodeat)
        ├── MySQL 8 (127.0.0.1:3306, 仅本机)
        └── Redis (127.0.0.1:6379, 无密码)  ← 团队购物车 ggc:cart:{team_id}（重启/多 worker 共享）
```

- **前端**：nginx 站点根 `/opt/good-good-eat/h5_dist`，监听 **7788**（备案与 HTTPS 就绪前用「IP + 端口」过渡；`server/deploy/nginx-goodgoodeat.conf` 是域名/443 就绪后的升级模板）
- **后端**：systemd 服务 `goodgoodeat`，工作目录 `/opt/good-good-eat/server`，`.env` 由服务读取（`EnvironmentFile`）
- **Redis**：团队协作购物车存储（`server/app/ws/cart_store.py`），Redis 不可用自动回落内存（不阻断启动）

## 2. 常规发布流程（每次发版）—— 核心操作

> 特点：**增量发布**，零停机衔接（后端重启约 3~5s），发布包不入 git、不碰服务器 `.env`/`.venv`。
> 前置：本机 h5 工程已 `pnpm install`；能 ssh 到服务器（本机 dsh 环境可直接用 ssh 工具，或命令行 `ssh root@47.108.216.57`）。

### 2.1 本机打包

```powershell
# Windows PowerShell，仓库根目录
powershell -ExecutionPolicy Bypass -File deploy\package.ps1
```

产出并校验：
- `h5-deploy.zip`（zip 内 `h5/dist/...`，约 0.3MB）
- `server-deploy.zip`（zip 根为 server/ 内容，排除 `.venv/.env/tests/本地调试产物`，约 0.7MB）

### 2.2 上传到服务器

```bash
scp h5-deploy.zip server-deploy.zip root@47.108.216.57:/opt/good-good-eat/
# 或使用 dsh 的 ssh_upload 工具（目标 /opt/good-good-eat/ 下同）
```

### 2.3 服务器端发布

```bash
ssh root@47.108.216.57
cd /opt/good-good-eat
# 后端与前端互不依赖，顺序任意
bash deploy/release-server.sh      # 解压覆盖 → 补 .env 键 → 重启 goodgoodeat → healthz
bash deploy/release-h5.sh          # 备份 → 替换 h5_dist → 校验 7788
bash deploy/verify.sh              # 统一验证清单
```

`verify.sh` 预期输出（关键项）：
- `/healthz` → `{"code":0,"message":"ok",...}`
- `/api/v1/categories` → 分类 JSON
- AI 路由 → `data: {"type":"error","message":"AI 功能未配置"}`（未配 key 属正常降级）
- `redis-cli ping` → `PONG`
- nginx 7788 → `HTTP/1.1 200 OK`

### 2.4 变更 AI 密钥（启用线上 AI）

```bash
# 服务器 /opt/good-good-eat/server/.env 增加/修改：
#   AI_MODEL=你的模型名
#   AI_API_KEY=你的密钥
systemctl restart goodgoodeat
```

不填则功能优雅禁用（AI 页提示「AI 功能未配置」），其余功能不受影响。

## 3. 首次初始化（新服务器）

1. 系统装 `git curl nginx gcc make openssl-devel bzip2-devel libffi-devel zlib-devel`
2. 装 `uv`，把代码拉到 `/opt/good-good-eat`（[deploy-server.sh](../server/deploy/deploy-server.sh) 内置 git clone 与全流程）
3. 执行 `server/deploy/deploy-server.sh` ✅ 完成：MySQL8 / venv（uv sync）/ 迁移 / 种子 / systemd `goodgoodeat` / 防火墙
4. （2026-08-27 起新增）**必须再执行 Redis 准备**：

```bash
bash /opt/good-good-eat/deploy/setup-redis.sh    # Redis 服务 + venv redis-py + .env REDIS_URL
```

5. 前端站点：把 `h5-deploy.zip` 发布为 `h5_dist/`（§2.2/2.3），并放置 nginx 站点配置（当前用 7788 端口版；域名+HTTPS 就绪后替换为 `server/deploy/nginx-goodgoodeat.conf` 模板）
6. 首次初始化后自测：`bash deploy/verify.sh` 全绿

## 4. 服务器 .env 配置项

> 位于 `/opt/good-good-eat/server/.env`，**不入库**；发布脚本只补缺失键、绝不覆盖已有值。
> pydantic-settings 大小写不敏感（`APP_*` 与 `app_*` 等价）。

| 键 | 说明 | 生产值（当前） |
|----|------|----------------|
| `DEBUG` | 生产必须 false | `false` |
| `DATABASE_URL` | MySQL（仅本机 127.0.0.1） | `mysql+pymysql://goodgoodeat:***@127.0.0.1:3306/good_good_eat?charset=utf8mb4` |
| `JWT_SECRET` | ≥32 位随机密钥（初始化时生成） | 随机值 |
| `CORS_ORIGINS` | H5 跨域 | `*` |
| `REDIS_URL` | 团队购物车存储 | `redis://127.0.0.1:6379/0`（无密码） |
| `AI_BASE_URL` | OpenAI 兼容 base | `https://api.openai.com/v1` |
| `AI_MODEL` | AI 模型（空 = 功能禁用） | 待填 |
| `AI_API_KEY` | AI 密钥（空 = 功能禁用） | 待填 |
| `WX_APPID` / `WX_SECRET` | 微信登录（有需要才配） | 服务器侧按需 |

## 5. 回滚

| 场景 | 方法 |
|------|------|
| 前端异常 | `h5_dist_bak_<TS>` 即上一版：`rm -rf h5_dist/* && cp -r h5_dist_bak_<最新TS>/* h5_dist/`（无 nginx reload 需求） |
| 后端异常 | `server_code_bak_<TS>.tgz` 即上一版代码：`cd server && tar xzf ../server_code_bak_<TS>.tgz && systemctl restart goodgoodeat` |
| 数据库 | 初始化与重大发布前手动 `mysqldump`（见 docs/03 §8）；每日备份建议 cron |

## 6. 备份与数据安全

- **代码**：每次发布前脚本自动备份（`h5_dist_bak_*` / `server_code_bak_*.tgz`），建议保留最近若干份，及时清理过期备份
- **数据库**：`mysqldump -ugoodgoodeat -p*** good_good_eat | gzip > backup_$(date +%F).sql.gz`，建议 cron 每日 + 保留 30 天
- **.env**：含数据库口令与 JWT 密钥，勿入库勿外传；换服务器时手动复制

## 7. 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| `verify.sh` 中 AI 返回「AI 功能未配置」 | 正常降级；在 `.env` 填 `AI_MODEL`/`AI_API_KEY` 后重启 |
| `release-server.sh` 后 healthz 挂了 | 看 `journalctl -u goodgoodeat -n 50 --no-pager`；多为依赖缺失，检查 redis-py（`bash deploy/setup-redis.sh`）或语法错误（本地先 `pytest` 过一遍） |
| 站点 80 端口是 nginx 欢迎页 | 站点在 **7788** 端口（IP+端口过渡方案）；备案/域名就绪后改用 443 模板并 80→443 跳转 |
| 团队购物车重启后丢失 | 说明落到内存回退（Redis 未起/redis-py 缺失）→ 执行 `setup-redis.sh`，确认 `redis-cli ping` PONG |
| 本机 `build:h5` 报 esbuild `EPERM` | 文件沙箱限制（named pipe）；在完整权限环境跑 `deploy/package.ps1` 即可 |
| 想用 git 方式更新服务器？ | 服务器虽为 git clone，日常发布**统一走 zip**：避免覆盖 `.env/.venv`、避免与本地未推分支错位；git 仅用于初始化与审计 |

## 8. 与 CI 的关系（现状说明）

当前为**人工增量发布**（§2）；未来若要自动化，可直接把 `package.ps1` 的打包段放进 GitHub Actions，产物作为 workflow artifact 上传服务器执行 `release-*.sh`。WebSocket 长连接场景下后端多 worker 已通过 Redis 共享购物车，发布（重启）只影响连接瞬断，无数据丢失。
