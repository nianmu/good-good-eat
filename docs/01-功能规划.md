# 好好吃饭 · 功能规划（当前版）

> 版本：v3（2026-08-26）｜对齐当前已上线功能（活动/饭局重构 + 菜品自建与可见性）
> 定位：**家庭 / 小聚场景的多人协同点菜 + 做菜协作工具**。
> 核心原则：**不涉及支付**，是美食记录与烹饪协作工具，不是商家收款系统。

---

## 一、产品定位

| 维度 | 说明 |
|------|------|
| 一句话 | 一日三餐，就用好好吃饭——一次饭局，全家人一起点菜、按菜指派厨师、逐道推进 |
| 目标场景 | 家庭日常做饭、朋友小聚、情侣做饭、社团聚餐 |
| 核心价值 | 解决"今天吃什么"决策难题 + 多人点菜不重复不遗漏 + 每道菜都有负责人和进度 |
| 不做什么 | 不做支付、不做外卖配送、不做商家收款、不做社区 |

---

## 二、角色体系

| 角色 | 职责 | 关键操作 |
|------|------|----------|
| 点菜人（默认） | 选菜、参加饭局 | 浏览菜单、加购物车、加入饭局、参加多个团队 |
| 厨师 | 做指定的菜 | 认领/被指派菜品，逐道推进 待备菜→待烹饪→烹饪中→已完成 |
| 组织者 | 管理团队与饭局 | 创建团队、邀请成员、指定团队固定厨师、推进饭局阶段 |

> - 一个用户可同时是点菜人和厨师（家庭场景：妈妈点菜也是她做菜）。
> - 厨师两种方式：团队固定厨师；饭局内单菜指派（"我来做"或指定成员）。

---

## 三、团队模型

| 概念 | 说明 |
|------|------|
| **团队** | 持久化组织，如"我家"、"美食社团"。成员相对固定。 |
| **团队成员** | 组织者邀请加入（邀请码），成员可自退；组织者可移除成员。 |
| **团队厨师** | 团队可指定固定厨师；饭局内单菜仍可单独指派。 |

## 四、核心功能模块

### 模块 1：菜品与菜单

#### 1.1 菜品浏览
- 分类切换（6 类）：荤菜 / 蔬菜 / 主食 / 汤 / 能量 / 凉菜
- 菜品卡片：emoji 色块、名称、评分、价格（仅参考）、简介
- 搜索：按菜名/食材
- 菜品详情：食材清单、做法（关联公开菜谱）、收藏、加购物车

#### 1.2 用户自建菜品（B 方案：一道菜 = 一份做法）
- 菜单页「＋新菜品」→ 填写名称/emoji/色块/分类/价格/食材/做法步骤
- **可见性三态**（创建后可改）：
  | 可见性 | 谁可见 |
  |--------|--------|
  | 公开 | 所有人（含游客） |
  | 团队公开 | 我加入的所有团队的**当前**成员（动态跟随，成员离开即不可见） |
  | 仅自己 | 只有我 |
- 所有读菜入口按可见性过滤：菜单列表/详情、随机/推荐、冰箱推荐、收藏、饭局点菜
- 创建菜品时可带做法 → 自动生成关联菜谱（"一道菜=一份做法"闭环）

#### 1.3 智能辅助
- 随机点菜（均衡/惊喜/营养三模式）
- 按人数推荐一轮搭配（荤/素/汤/主食）

### 模块 2：饭局（活动）—— 多人协同点菜 + 做菜

一次饭局 = 一个活动，生命周期：

```
点菜中 → 备菜中 → 烹饪中 → 已完成（全部菜 done 自动完成）
```

- **点菜中**：成员加菜（菜单/购物车→饭局），WS 实时同屏；已点菜可移除
- **备菜中**：食材汇总（日常饭局联动冰箱：已有高亮/缺口置灰）；未指派厨师的菜先指派
- **烹饪中**：每道菜按 `待备菜→待烹饪→烹饪中→已完成` 逐道推进（仅该菜厨师可推）
- **已完成**：全部菜做完自动完成；可「再来一餐」复用、可「存为菜谱」

**联动规则**（菜品进度 ↔ 总体流程）：
- 总进度由真实数据推导：备菜阶段按食材备齐率、烹饪阶段按完成菜品数
- 三闸门：没点菜不能进备菜 / 有菜没厨师不能开始制作 / 有菜没完成不能完成饭局
- 单菜推进按阶段解锁（备菜阶段才能标记备好，烹饪阶段才能标记完成）

### 模块 3：菜谱库

- **公开菜谱**（平台，每道菜配一篇做法，seed 生成）+ **我的菜谱**（用户自建）
- 用户自建菜谱：名称/emoji/色块/描述/食材/步骤/耗时/难度/**分类**/是否公开
- **分类复用菜单 6 类**：菜谱库按分类 Tab 筛选
- 收藏菜谱；公开菜谱所有人可浏览
- 菜谱与菜品互通：菜品详情「查看完整做法」跳对应菜谱；饭局「存为菜谱」一键把菜单存为菜谱草稿

### 模块 4：厨房

- **厨房冰箱**：记录现有食材（名称/数量），推荐能做的菜（命中 ≥2 种食材）
- **厨房菜篮**：待采购清单，勾选已买
- **我的收藏**：收藏的菜品 + 收藏的菜谱

### 模块 5：饮食计划

- 保存我的饮食计划（名称/备注 + 菜品清单 + 数量）
- 一键加入购物车；支持按推荐组合预填

### 模块 6：个人中心

- 用户信息：头像/昵称/标识码/游客标识（统一账号体系见 docs/05）
- 统计三格：总饭局 / 点过的菜 / 收藏
- 我的团队（管理/退出）、使用指南、系统主题（浅色/深色/跟随系统）
- TabBar：菜谱 / 饭局 / 我的（三入口）

## 五、页面结构

```
TabBar（3 个主入口）
├── 菜谱 menu          ← 分类+菜品列表+搜索+新菜品+购物车入口
├── 饭局 activities    ← 饭局列表（状态筛选）+「新建」
└── 我的 profile       ← 个人信息+统计+团队+功能宫格

关键子页面
├── activity-detail    饭局详情：进度条/成员/菜品（指派厨师+逐道推进）/食材汇总
├── dish-detail        菜品详情：食材/做法（公开菜谱跳转）/收藏/可见性标签/加购
├── dish-edit          新建菜品：表单+可见性三态+团队选择+做法（可选）
├── cart               购物车：发起饭局（团队+类型）/加入已有饭局
├── recipe-list        菜谱库：公开/我的 + 分类 Tab
├── recipe-edit / recipe-detail  菜谱创建编辑 / 详情（步骤/收藏）
├── fridge / basket    冰箱 / 菜篮
├── plans / plan-edit / plan-detail  饮食计划
├── team-list / team-detail  团队管理
├── auth / welcome / guide / theme  登录 / 引导 / 使用指南 / 主题
```

## 六、技术架构

| 层 | 技术 | 说明 |
|----|------|------|
| 前端 | Taro 4 + React + NutUI（H5） | `build:h5` 产物 SPA；跨端可出 weapp |
| 后端 | Python 3.13 + FastAPI + SQLAlchemy 2.0 | 模块化单体 REST API |
| 数据库 | MySQL 8（utf8mb4）+ Alembic 迁移 | 见 server 模型 |
| 实时同步 | WebSocket `/ws/team/{teamId}` | 饭局加菜/状态变更同屏广播 |

**数据模型要点**：
- `users / user_identities`（统一账号，docs/05）
- `teams / team_members`（团队）
- `categories / dishes`（菜品；`created_by/visibility/team_id` 支撑自建与三可见性）
- `activities / activity_items / activity_ingredients`（饭局主线）
- `recipes / recipe_favorites`（菜谱；`category_id` 关联分类、`dish_id` 关联菜品）
- `fridge_items / basket_items / favorites / plans / plan_items`
- 已下线：`orders / order_items`（旧按人下单，2026-08 活动重构后删除）、`messages`（站内消息，通知由 WS 取代）

## 七、状态机

### 饭局级 `activities.status`
```
ordering(点菜中) —[至少 1 道菜]→ preparing(备菜中) —[所有菜有厨师]→ cooking(烹饪中) —[全部菜 done]→ completed
```
- 自动完成：cooking 下最后一菜 done → 活动自动置 completed

### 菜级 `activity_items.status`
```
pending(待备菜) → prepared(待烹饪) → cooking(烹饪中) → done(已完成)
```
- 阶段解锁：`→prepared` 需活动 ≥备菜中；`→cooking/done` 需活动 ≥烹饪中
