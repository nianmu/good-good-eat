## 1. 总体架构

```
┌──────────────────┐   HTTPS REST + WebSocket   ┌────────────────────┐
│  Taro 4 + React   │ ◄───────────────────────► │  FastAPI 后端       │ ◄─► MySQL8
│  h5/（H5 SPA）     │   JSON + /ws/team/{id}    │  server/            │
│                   │                            │   （模块化单体）      │
└──────────────────┘                            └────────────────────┘
   build:h5 → 静态 SPA（nginx :7788）               uvicorn :8000（systemd 托管）
```

- 前端 `h5/` 是唯一实现（Taro 跨端，当前以 H5 部署；weapp 可同源码编出）。
- 后端 `server/`：FastAPI 模块化单体，同步 SQLAlchemy 2.0（pymysql）+ Alembic。
- 认证：游客 / 用户名密码 / 微信 三渠道，统一 JWT（见 docs/05-auth-redesign.md）。
- WebSocket：`/ws/team/{teamId}` 房间广播，饭局/购物车状态变更实时同步。
- 生产：阿里云轻量 47.108.216.57；nginx :7788 静态 H5 + 反代 API/WS；`goodgoodeat.service` 托管 uvicorn；MySQL 8 :3307（本机开发）/ 服务器 :3306。

## 3. 后端设计（server/）

### 3.1 目录结构（当前）

```
server/
  pyproject.toml / uv.lock / .env.example / alembic.ini
  alembic/versions/          # 迁移：基线 → phases/activities/recipes/dish-visibility/删除旧订单
  app/
    main.py                  # 入口：路由/CORS/WS/异常/healthz
    core/                    # config / db / security / responses / exceptions
    models/                  # activity, dish, recipe, team, user, plan, fridge, basket, favorite
    schemas/                 # Pydantic 请求/响应
    api/v1/                  # auth / teams / dishes / activities / recipes / fridge / basket / favorites / plans
    services/                # auth_service（业务规则）
    ws/                      # manager（房间）+ handlers（事件分发）
  tests/                     # conftest + 各模块测试（当前 78 项）
  seed/seed_data.py          # 分类/菜品/公开菜谱种子（幂等）
```

分层约定：`api`（薄路由）→ `models/schemas`（数据）；业务规则就近放在路由/服务层，保持单一职责。

### 3.2 数据模型（当前，9 组表）

| 域 | 表 | 说明 |
|----|----|------|
| 账号 | `users` / `user_identities` | 统一账号 + 渠道身份（docs/05） |
| 团队 | `teams` / `team_members` | 团队（可空固定厨师 chef_id）+ 成员关系（organizer/member） |
| 菜品 | `categories` / `dishes` | 6 类；`dishes` 含 `created_by/visibility(public\|team\|private)/team_id`（自建与可见性） |
| 饭局 | `activities` / `activity_items` / `activity_ingredients` | 活动 + 菜项（chef/status）+ 食材备齐 |
| 菜谱 | `recipes` / `recipe_favorites` | 菜谱含 `category_id`（分类）与 `dish_id`（关联菜品）；收藏 |
| 厨房 | `fridge_items` / `basket_items` / `favorites` | 冰箱 / 菜篮 / 菜品收藏 |
| 计划 | `plans` / `plan_items` | 饮食计划 |
| ~~订单~~ | ~~orders / order_items~~ | **已删除**（2026-08 活动重构） |
| ~~消息~~ | ~~messages~~ | **已删除**（通知由 WS 取代） |

### 3.3 核心状态机

- 活动：`ordering → preparing → cooking → completed`（单向，含三闸门 + 自动完成，见 01 §七）
- 菜项：`pending → prepared → cooking → done`（厨师推动，按活动阶段解锁）
- 菜品可见性：`public / team / private`（所有读菜入口统一过滤）

### 3.4 API 一览（/api/v1）

| 方法/路径 | 鉴权 | 说明 |
|-----------|------|------|
| `POST /auth/guest` `POST /auth/register` `POST /auth/login` `POST /auth/wx-login` | 否 | 三渠道登录/注册 |
| `GET /me` | 是 | 当前用户 + 团队 + 统计（总饭局/点菜数/收藏） |
| `GET /categories` | 否 | 分类列表 |
| `GET /dishes`（category_id/keyword/mine/page） | 可选 | 菜品列表（按可见性过滤） |
| `POST /dishes` / `PUT /dishes/{id}` | 是 | 自建/编辑菜品（隐藏 recipe 对象一键建菜谱） |
| `GET /dishes/random` `GET /dishes/recommend` | 可选 | 随机/按人数推荐（可见池） |
| `GET /dishes/{id}` | 可选 | 菜品详情（不可见 404） |
| `POST /dishes/{id}/favorite` / `DELETE` | 是 | 收藏/取消 |
| `POST /teams` `POST /teams/join` `GET /teams/{id}` `PUT /teams/{id}/chef` `POST /teams/{id}/leave` `DELETE /teams/{id}/members/{uid}` | 是 | 团队管理 |
| `GET /teams/{id}/cart` | 是 | 团队购物车统计 |
| `POST /activities` `GET /activities` `GET /activities/{id}` | 是 | 饭局 CRUD + 详情 |
| `POST /activities/{id}/status` | 是 | 阶段流转（闸门校验） |
| `POST /activities/{id}/items` `DELETE .../items/{iid}` `PUT .../items/{iid}/chef` `PUT .../items/{iid}/status` | 是 | 菜项：加菜/删/改厨/推进 |
| `GET PUT /activities/{id}/ingredients...` | 是 | 食材备齐 |
| `GET /recipes`（owner/category_id） `GET/POST/PUT/DELETE /recipes/{id}` `POST/DELETE /recipes/{id}/favorite` `GET /recipes/favorites` `GET /recipes/by-dish/{id}` | 混合 | 菜谱库 |
| `GET/POST/DELETE /fridge` `GET /fridge/suggest` | 是 | 冰箱 |
| `GET/POST/PUT/DELETE /basket` | 是 | 菜篮 |
| `GET/POST/DELETE /plans` `GET/DELETE /plans/{id}` | 是 | 饮食计划 |
| `GET /healthz` | 否 | 健康检查 |

统一响应：`{"code": 0, "message": "ok", "data": ...}`；错误码段 40xxx 客户端 / 50xxx 服务端。

### 3.5 可见性实现要点

- `visible_dish_conds(db, user)`：游客见 public；登录见 public + 自己的 private + 所在团队 team 菜
- **team 动态跟随**：查询时 join `team_members` 现算，不落冗余可见名单
- 不可见返回 404（不区分 403/404，避免探测）
- 全接入点：dishes 列表/详情/随机/推荐、favorites、activities 点菜、plans、fridge/suggest、recipes/by-dish

## 6. 部署实践（打翻重来式）

- 本地构建前端 → `tar` 打包 `h5/dist` → scp 到服务器解压到 `h5_dist`（nginx :7788）

- 数据变更走迁移链；**表结构可推翻重来**（2026-08 已删订单/消息两张旧表族）
