## 2. 总体架构

```
┌──────────────────┐   HTTPS REST + WebSocket    ┌─────────────────────┐
│   Taro 跨端前端      │ ◄────────────────────────► │   FastAPI 后端       │ ◄─► MySQL8
│   h5/（TS+React）    │   JSON + 实时同步（三期）     │   server/            │
│   build:h5 → 浏览器   │                             │   （模块化单体）       │
│   build:weapp → 小程序│                             │                       │
└──────────────────┘                             └─────────────────────┘
   浏览器真机预览 / 微信开发者工具 weapp 真机预览       uvicorn 单进程起步
```

- 两端通过 `/api/v1/*` REST 接口通信；第三期增加 `/ws/team/{teamId}` WebSocket 房间。
- 认证：`wx.login` → `code2session` 换 openid → 签发 JWT；未登录用户走游客模式（`users.is_guest=1`），对应原型中不依赖微信能力的预览路径。
- 本项目**不涉及支付**：金额仅作参考展示，订单不需要支付回调/对账。

## 4. 后端设计（server/）

### 4.1 目录结构

```

    core/

      db.py                 # engine / session 工厂（同步 pymysql）
      security.py           # JWT 签发与校验、密码/口令工具
      deps.py               # 依赖注入：get_db / get_current_user
    models/                 # SQLAlchemy 模型（见 §4.2）
    schemas/                # Pydantic 请求/响应模型
    api/v1/
      router.py             # 汇总路由
      auth.py  users.py  teams.py  dishes.py  orders.py
      kitchen.py            # 四期占位
      messages.py           # 四期占位
    services/               # 业务层：order_service / team_service / pickup_service
    ws/                     # 三期：manager.py（连接管理）handlers.py（事件分发）
  tests/
```

分层约定：`api`（薄路由）→ `services`（业务规则）→ `models/schemas`（数据）；服务层可独立单测。

### 4.2 数据模型（核心表）

> 字段以实施时迁移脚本为准；此处为设计基线。均含 `id BIGINT PK AI`、`created_at`、`updated_at`；金额 `DECIMAL(10,2)`。

| 表 | 关键字段 | 说明 |
|----|----------|------|
| **users** | `nickname`、`avatar`、`user_code VARCHAR(12) UNIQUE`、`is_guest TINYINT` | 跨端统一账号（已解耦自 openid；微信身份通过 user_identities 绑定，见 docs/05）；标识码供邀请识别（原型 38243244） |
| **teams** | `name`、`invite_code VARCHAR(8) UNIQUE`、`owner_id→users`、`chef_id→users NULL` | 团队；固定厨师可空（空则支持成员认领） |
| **team_members** | `team_id`、`user_id`、`role ENUM('organizer','member')`，`UNIQUE(team_id,user_id)` | 成员关系 |
| **categories** | `name`、`icon`、`sort_order` | 菜品分类（原型 6 类） |
| **dishes** | `category_id→categories`、`name`、`price`、`rating`、`rating_count`、`description`、`emoji`、`color`、`image_url NULL`、`ingredients JSON`、`cook_time`、`difficulty`、`is_active` | 菜品；食材 JSON 为第四期菜谱留位 |
| **orders** | `order_no VARCHAR(32) UNIQUE`、`pickup_code VARCHAR(8)`、`team_id`、`user_id`（下单人）、`chef_id NULL`、`status ENUM(pending,accepted,cooking,ready,completed)`、`total_amount`、`total_count`、`pickup_date DATE` | 订单；取餐码+日期按团队日增量 |
| **order_items** | `order_id→orders`、`dish_id NULL`、`name/emoji/color/price`（快照）、`quantity` | 菜品快照，防菜品下架影响历史订单 |
| **messages**（四期） | `user_id`（接收人）、`type ENUM(order,team,system)`、`title`、`content`、`is_read` | 站内消息 |
| **recipes / fridge_items / basket_items**（四期） | 用户自建菜谱、冰箱库存、菜篮待购 | 四期建表，本期不进迁移 |

### 4.3 取餐码生成（pickup_service）

- 规则：**团队维度 + 当日递增短号**。`pickup_code = (该团队当日最大号 + 1)`，从 1001 开始；跨日重置。
- 实现：查询 `orders WHERE team_id=? AND pickup_date=CURDATE() ORDER BY pickup_code DESC LIMIT 1`，防并发用 `SELECT ... FOR UPDATE`（事务内）或唯一约束重试。
- 含义：拿到订单即口头喊「1002 好了」；与原型展示一致。

### 4.4 API 一览（/api/v1）

统一响应：`{"code": 0, "message": "ok", "data": ...}`；错误通过全局异常处理器输出统一结构。

| 方法/路径 | 鉴权 | 说明 |
|-----------|------|------|
| `POST /auth/wx-login` `{code}` | 否 | 微信 code 换 openid → 返回 `{token, user}` |
| `POST /auth/guest` `{nickname}` | 否 | 游客登录（保底路径）→ `{token, user}` |
| `GET /me` | 是 | 当前用户信息 + 团队列表 |
| `GET /categories` | 否 | 分类列表 |
| `GET /dishes?category_id=&keyword=&page=` | 否 | 菜品列表/搜索 |
| `GET /dishes/{id}` | 否 | 菜品详情 |
| `POST /teams` `{name}` | 是 | 创建团队（成为组织者） |
| `POST /teams/join` `{invite_code}` | 是 | 加入团队 |
| `GET /teams/{id}` | 是 | 团队详情（成员/厨师） |
| `PUT /teams/{id}/chef` `{user_id}` | 组织者 | 指定固定厨师 |
| `POST /orders` `{team_id, items:[{dish_id,quantity}]}` | 是 | 下单 → 生成取餐码，状态 pending |
| `GET /orders?page=&status=` | 是 | 我的订单列表 |
| `GET /orders/{id}` | 是 | 订单详情（含菜品快照/取餐码） |
| `POST /orders/{id}/accept` | 是 | 厨师接单（pending → accepted） |
| `POST /orders/{id}/status` `{status}` | 是 | 状态流转（accepted→cooking→ready→completed，单向校验） |
| `POST /orders/{id}/claim` | 是 | 无固定厨师时成员认领为厨师 |
| `GET /healthz` | 否 | 健康检查（DB 连通） |

### 4.5 认证与安全

- `wx-login`：`GET https://api.weixin.qq.com/sns/jscode2session?appid=&secret=&js_code=&grant_type=authorization_code`（测试号凭据后续配置）→ openid 找/建 user → 发 JWT。
- JWT：HS256，payload `{sub: user_id}`，有效期 30 天；`Authorization: Bearer <token>`。
- 游客模式：`/auth/guest` 创建 `is_guest=1` 用户（昵称必填，如「游客-A8F3」），token 同样签发；下单、建团队等需要身份的操作用游客身份兜底，不强制微信登录。
- CORS：开发期放行 `*`（真机预览无跨域概念，为开发者工具本地调试留口）。

### 4.6 WebSocket（第三期，本期预留设计）

- 路径：`/ws/team/{teamId}?token=JWT`；`ws/manager.py` 维护 `team_id → set[连接]`。
- 事件（JSON 消息，带 `event` 字段 + 递增 `seq`）：
  - `cart.upsert`（谁/哪道菜/数量）→ 广播给同房间
  - `order.created` / `order.status_changed` → 广播
  - `member.joined` / `member.claimed_chef` → 广播
- 心跳：客户端 30s ping，服务端 60s 无消息断连；断线重连后拉取房间全量快照补齐。

## 5. 小程序设计（miniprogram/）

原生四件套，无构建链：开发者工具「导入项目」→ 填 AppID 测试号目录打开。

### 5.1 目录结构

```
miniprogram/
  app.js / app.json / app.wxss（设计 token 与 prototype/styles/tokens.css 对齐）
  project.config.json
  utils/
    request.js        # Promise 封装：baseURL、token 注入、401 统一处理、错误 toast
    store.js          # 轻量全局状态：user/token、购物车（团队维度）
    ws.js             # 三期：WebSocket 封装（心跳/重连/房间订阅）
    util.js           # 格式化（金额/时间/取餐码）
  components/
    dish-card / qty-stepper / status-chip / empty-state
  pages/
    menu/             # 分类 + 菜品列表 + 随机点菜 + 底部下单栏（TabBar·菜谱）
    dish-detail/      # 菜品详情：大图/食材/做法/评分/加购
    cart/             # 购物车：数量调整/合计/提交下单
    orders/           # 订单列表（TabBar·订单）+ 角色切换：我的订单 / 厨师看板（三期）
    order-detail/     # 订单详情：取餐码 + 状态步骤条 + 复制订单信息（同原型）
    team-list/        # 我的团队 + 创建/加入
    team-detail/      # 团队成员/指定厨师/邀请码（三期开邀请码分享）
    messages/         # TabBar·消息（四期）
    profile/          # TabBar·我的：用户信息/团队入口/功能宫格（同原型）
```

TabBar 四入口：菜谱 / 订单 / 消息 / 我的，icon 用本地 PNG（`assets/icons/`）。

### 5.2 页面与数据流

- **菜谱页**：`onLoad → GET /categories + /dishes` → 左侧分类 + 右侧菜品（同原型布局）；点击菜品 → _dish-detail_；`+/-` 操作本地购物车并同步 `store.js`。
- **下单页（cart）**：读取 store 购物车 → 选团队（默认第一个）→ `POST /orders` → 成功跳转 _order-detail_（取餐码大字展示）。
- **订单列表页**：`GET /orders` 分页；卡片显示状态徽章 + 取餐码 + 金额；点卡片 → _order-detail_。
- **我的页**：`GET /me` 渲染用户/团队（同原型宫格）。
- 全部页面 error 态统一 `empty-state` 组件 + toast 提示。

### 5.3 与原型的一致性

- 设计 token（主绿 `#4CAF50`、间距 8px 体系、圆角、阴影）已定义于 `prototype/styles/tokens.css`，小程序 `app.wxss` 以 CSS 变量/常量方式对齐，保证视觉一致。
- mock 数据 `prototype/scripts/data/*.js` 作为种子数据源（`server/seed/` 复用），菜品字段一一对应。

## 7. 测试策略

- 后端：pytest + FastAPI `TestClient`（httpx 底层，同步用例）打真实路由；测试库 `good_good_eat_test`（MySQL8，session 级建/拆 schema，每用例清表）。

```jsonc
// POST /api/v1/orders  请求
{ "team_id": 1, "items": [ { "dish_id": 5, "quantity": 2 }, { "dish_id": 1, "quantity": 1 } ] }

// 响应
{
  "code": 0, "message": "ok",
  "data": {
    "id": 12, "order_no": "20260818-000012",
    "pickup_code": "1002", "status": "pending",
    "total_amount": 52.00, "total_count": 3,
    "items": [ { "name": "蒜蓉西兰花", "emoji": "🥦", "price": 12.00, "quantity": 2 } ]
  }
}
```

```jsonc
// 统一错误
{ "code": 40401, "message": "订单不存在或无权访问", "data": null }
```

错误码段：`40xxx` 客户端/鉴权、`50xxx` 服务端。
